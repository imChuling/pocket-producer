Phase 1 -- The Problem (15s)
00:00 - 00:15 Hook Musical Value 25%
On screen
  1. Audiotool open with your unfinished project -- timeline visible, a few tracks with content, some empty
  2. Slowly scroll the timeline left-right so it feels alive and real
  3. Maybe hover over a track or two
Voiceover
This is a track I never finished. I have dozens of my own loops and sketches somewhere in my library. The problem isn't making more sounds -- it's knowing which of them could grow into this.
Why this matters: This establishes the core problem judges need to understand. Every musician has this experience. Don't rush it -- let them feel it.

00:45 - 01:10 Session fingerprint Nexus Document Read Innovation 30%
On screen
  1. Session summary panel appears: "What we read from your session"
  2. Point at each field -- Tempo (e.g. "120 BPM"), Key ("not available" -- be honest), Tracks ("4"), Track types ("drums, synth"), Playhead ("12.5s")
  3. Hover over "Key: not available" briefly -- this is honesty
  4. Click the text intent field: "What are you going for?"
  5. Type: "dark bass to sit under these drums"
Voiceover
It reads the open session through Nexus: tempo, track count, what instrument roles are already covered, where my playhead is. Audiotool documents don't carry a key signature, so it says "not available" rather than guessing.

I can also add intent in my own words. Right now I want a dark bass to sit under these drums.
Innovation proof: Session compatibility, not similarity. The system reads what's already there (tempo, roles, playhead) and asks what's missing -- not "find something that sounds like this." The "Key: not available" is intentional: missing data is reported, never imputed.
Phase 3 -- Core Workflow (1:30)
01:10 - 01:25 Intensity + model controls User Control UX 20%
On screen
  1. Below the session summary: the control bar with Nudge / Suggest / Explore toggle + model dropdown + "Suggest 3" button
  2. Click through intensity levels: Nudge (1 result), Suggest (3), Explore (6) -- show the toggle changing
  3. Open the model dropdown: show Rules (default) and Fusion available
  4. Leave it on Suggest mode + Rules model
Voiceover
I control how many suggestions I want. Nudge gives me one; Suggest gives three; Explore gives six. The model is selectable too -- Rules is the transparent default; Fusion is a learned ranker I can switch to. More on why that's a choice in a moment.
UX principle: The musician sets the intervention level, not the system. This is "one primary action per state" -- the interface doesn't overwhelm.
01:25 - 01:55 Ranking + evidence Grounded Ranking Innovation 30%
On screen
  1. Click "Suggest 3" (sparkle icon button)
  2. Loading spinner briefly, then three candidate cards appear in a grid
  3. Each card shows: fragment title, "Why this now" section with colored evidence chips
  4. Hover over first card's evidence chips: e.g. role gap fill 120 BPM match tag: bass
  5. Move to second card -- show different evidence (e.g. tempo match but different role)
  6. Note the small "Served by rules-v1" badge -- the system tells you which model answered
Voiceover
Three suggestions from my own library. Each one carries structured evidence: this fragment fills a role my session doesn't have yet, its tempo is close, its tags match my intent. These labels come from the ranker's actual features -- tempo proximity, role gap detection, tag overlap. Never generated prose, never a black-box score. Every reason you see is a real signal the ranker used.
Evidence chip types (color-coded in UI):
Green = role/track gap fill   Tan = tempo/key match   Teal = tag overlap   Blue = intent match   Purple = harmonic fit   Coral = timbral match
This is the key innovation shot. Spend time here. Hover slowly over each chip so judges can read them. The "Why this now" label is the headline.
01:55 - 02:10 Preview + listen Preview Before Commit UX 20%
On screen
  1. Click Preview (play icon) on the best candidate
  2. Audio plays through system audio -- let it play 3-5 seconds
  3. Optionally preview a second candidate to show comparison
Voiceover
Before committing, I can preview. This is my own audio, from my own library -- Pocket Producer doesn't generate anything.
Musical value: "Your own material, not generated" is a core differentiator. The preview is the musician staying in control.
02:10 - 02:35 Insert into Audiotool Real Nexus Write Technical 25%
On screen
  1. Click "Insert into Audiotool" button on the chosen candidate
  2. Loading spinner on the button while the Nexus transaction runs
  3. Green confirmation bar appears: "Inserted 'Fragment Title' at 12.5s -- check your Audiotool timeline" + Undo button
  4. Switch to Audiotool tab
  5. Show the timeline: new sample visible at the playhead position
  6. Zoom in on the inserted sample to make it clearly visible
Voiceover
Insert. One Nexus transaction: it uploads the sample, waits for the server to confirm, then places it on the timeline at my playhead position. This is a real write into the real project -- not a simulation.
Show the Audiotool timeline BEFORE the insert (previous shot's Audiotool view) and AFTER. The before/after is proof of real write. Zoom in so the new sample is clearly visible.
02:35 - 02:55 Undo Exact Undo via Receipt Innovation 30% UX 20%
On screen
  1. Switch back to Pocket Producer
  2. The green bar still shows: "Inserted 'Fragment Title' at 12.5s" with the Undo button
  3. Click Undo
  4. Green bar disappears
  5. Switch to Audiotool: the sample is gone from the timeline
  6. Hold on the clean timeline for 2 seconds -- same state as before the insert
Voiceover
And undo. It doesn't just delete something -- it restores the exact prior entity set using the insert receipt. The system proposes; I decide. Every action is reversible.
Technical detail worth mentioning: The undo works from an "insert receipt" that records every entity the transaction created. This is validated against Audiotool's official document validator in tests. Not a generic "delete last thing" -- an exact reversal.
Three timeline states must be visible across shots 8-9: before insert, after insert, after undo. This is the strongest proof of real read/write integration.
Phase 4 -- Innovation + Research + Close (50s)
02:55 - 03:10 Model honesty Honest Uncertainty Innovation 30%
On screen
  1. Back in Pocket Producer, open the model dropdown
  2. Switch from Rules to Fusion
  3. Click "Suggest 3" again -- new results appear
  4. Note the badge: "Served by fusion-5sig-v1"
  5. Evidence chips may differ from the Rules results
Voiceover
The fusion model is a five-signal learned ranker. It's available, but it's not the default -- because our offline evaluation found that its advantage over the rules baseline depends on how the weak-supervision labels are constructed. Rather than silently using the fancier model, we let you choose, and we tell you which model answered.
This is the core innovation pitch: Most tools hide their model choices. Pocket Producer makes them explicit and selectable, grounded in actual evaluation evidence. "Honest uncertainty as a design principle."
03:10 - 03:15 Fallback architecture Graceful Degradation Technical 25%
On screen
  1. Brief: show the "Served by rules-v1" or mention the fallback badge
Voiceover
If the fusion model is unavailable, the system falls back to the rules ranker automatically and tells you. The core loop never depends on a remote model.
03:15 - 03:35 Research backing (ISMIR) Measured System Innovation 30%
On screen
  1. Cut to: README on GitHub -- scroll to the results tables (dev set + held-out)
  2. Show the held-out sensitivity table: LAION-CLAP vs MS-CLAP results, the 7.8pp swing
  3. Brief flash of the sensitivity figure (heldout-sensitivity.png) if you have it open
Voiceover
This isn't decoration. We evaluated against six baselines on a frozen held-out split. The learned fusion shows a 7.8 percentage-point swing on the hardest examples depending on which audio embedding and training configuration you use. That sensitivity is why the rules baseline is the default and the fusion is opt-in. The same evaluation is submitted to ISMIR 2026 as a Late-Breaking Demo paper.
ISMIR mention adds credibility: It signals peer review and research rigor. Judges care about whether the technical claims are substantiated. The frozen split + sensitivity analysis is strong evidence. Don't dwell on numbers -- the point is "we measured it and the answer is nuanced."
