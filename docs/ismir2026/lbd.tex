\begin{abstract}
Music continuation is not a similarity problem: the loop that best
matches a session is not necessarily the one that helps a musician
move it forward.  Pocket Producer operationalizes this distinction
inside the Audiotool DAW\@: it fingerprints the live session via the
Nexus SDK (tempo, CLAP embeddings of session audio) and ranks
Freesound Loop Dataset candidates with a five-signal fusion trained
on pack co-membership weak labels---proxy supervision available
before any interaction data exists---selectable alongside a
transparent rules default.  Offline evaluation shows the apparent ranking gain
changes substantially with weak-label construction, negative regime,
and embedding representation.  Since the proxy does not encode the
creative objective, every recommendation is an inspectable,
reversible \emph{proposal}---previewed with per-signal evidence,
inserted in a single undoable transaction, logged for future
personalization---rather than an autonomous creative decision.
\end{abstract}

\section{Introduction}\label{sec:intro}
% ==================================================================

When a musician returns to an unfinished loop-based project, the
question is not ``what sounds similar?''\ but ``what would be useful
as the next step?''
Loop compatibility~\cite{chen2020neuralloop,lattner2022samplematch,yi2024drum2bass,roychaudhuri2026loopmatcher},
stem coherence~\cite{ciranni2025cocola,nistal2024diffariff,riou2025stemretrieval},
session-conditioned generation~\cite{he2025tomi}, and reversible
co-creation~\cite{elkins2025dawzy} all address parts of this problem.
We define \textbf{continuation utility} as the property that a
candidate helps the musician make progress in the current session;
unlike similarity it is asymmetric and context-dependent.

We contribute: (1)~a problem formulation that separates continuation
utility from similarity and compatibility; (2)~empirical evidence
that ranking conclusions drawn from a weak proxy shift with label
construction, negative regime, and embedding representation;
(3)~a deployed system that turns this finding into interaction
design: proposal-based retrieval with per-signal evidence, preview,
reversible insertion, and feedback logging.

\subsection{Session Fingerprinting}\label{sec:fingerprint}

The live Audiotool session (Figure~\ref{fig:system}) is read via the
Nexus SDK, which exposes the project's devices, regions, and
referenced audio samples in real time.
The system extracts the project tempo from the document metadata and
collects up to eight unique audio samples referenced by regions in the
arrangement.  Each sample is embedded with
CLAP~\cite{elizalde2023clap}; the resulting vectors form the
session's timbral fingerprint.  When no session audio is available
(empty project or no sample-backed regions), the system falls back to
non-audio signals only.

\subsection{Multi-Signal Ranking}\label{sec:ranking}

Five signals score each FSLD~\cite{ramires2020fsld} candidate against
the session fingerprint:
(i)~mean-pooled and (ii)~max-pooled CLAP cosine similarity to session
samples, (iii)~tempo proximity, (iv)~key compatibility, and (v)~tag
Jaccard overlap between candidate tags and tags from the session's
audio fragments.
A logistic fusion trained with BPR loss~\cite{rendle2009bpr} on
Freesound pack co-membership weak labels
(Section~\ref{sec:fusion}) combines these into a single score.
A hand-tuned \emph{rules} baseline over non-audio session signals
serves as the default ranker; the fusion is selectable and falls
back to rules when no session audio is available.

\subsection{Proposal Interface}\label{sec:proposal}

The title's ``user-controlled proposal'' is a deliberate design
choice, not a fallback from poor accuracy.  Pack co-membership is a
proxy for timbral compatibility, not continuation utility; even a
perfect ranker under this label would not capture arrangement
context, creative intent, or genre conventions.
The design question is not whether the ranker can optimize the
proxy, but whether the proxy should hold final creative authority;
the interface answers by keeping the musician in the loop at every
step.

Each candidate is surfaced for in-context preview with per-signal
evidence: reason chips naming the signals that favored it (timbral
closeness to session regions, tempo fit, shared tags), so the
musician can assess \emph{why} the system ranks it highly and judge
whether those reasons apply to their current goal; signals that
contribute nothing emit no evidence.
An accepted candidate is inserted via a single Nexus transaction;
\emph{undo} reverts the insertion and retracts the candidate's tags
from the ranking context, so subsequent recommendations are not
biased by the undone choice.
Acceptance, rejection, and undo events are logged for future
personalization (not yet evaluated).

\subsection{Deployed Model}\label{sec:deployed}

The deployed ranker follows the same five-signal recipe but is a
separate production model with four stated deltas: MS-CLAP embedding
space (offline evaluation uses LAION-CLAP Music); source-weighted BPR
(hard\_similar$\times$2.0, mean over 5 seeds); key constant zero
online (Audiotool documents lack key-signature metadata); tag context
drawn from session fragments rather than pack siblings.

\section{Weak-Label Fusion}\label{sec:fusion}
% ==================================================================

From the FSLD~\cite{ramires2020fsld} we kept only sounds with a
true Freesound pack (1,797 items, 605 packs), discarding items
grouped only by uploader.
Each eligible pack with at least three items yields one leave-one-out query per item, with
same-pack siblings as positives and cross-pack items as negatives in
three difficulty tiers (\emph{easy}: tempo/key mismatch;
\emph{hard\_tempo\_key}: compatible tempo and key;
\emph{hard\_similar}: highest cosine to the positive from another
pack).
A 121-source held-out split (seed 20260810) was committed to version
control together with the evaluation protocol \emph{before} any
evaluation ran.
Development uses only the 484 train sources; the 171 with $\geq$3
items form queries (981 examples), the rest contribute negatives
only.
LAION-CLAP Music~\cite{wu2023laionclap} (512-dim) provides the
embedding backbone.

On the train side (mean over 5 source-grouped splits), frozen cosine
reaches 0.929 overall and 0.814 on hard\_similar; five-signal fusion
reaches 0.925 and 0.813.
Under pack-only labels the fusion advantage is gone: $-0.03$\,pp on
hard\_similar, and fusion trails cosine on hard\_tempo\_key by
2.1\,pp on average (negative in all 5 splits).
These development-set numbers are descriptive; inference is reserved
for the held-out analysis (Section~\ref{sec:observations}).

\section{Observations}\label{sec:observations}
% ==================================================================

The weak label measures pack co-membership, not continuation
utility; the observations below chart where the proxy breaks
down---and the feedback log of Section~\ref{sec:proposal} is
designed to eventually ground ranking in in-session evidence
instead.
Four lines of evidence jointly motivate treating the fusion as a
proposal rather than a decision.
%
\textbf{Label sensitivity.}\enspace An earlier corpus treated
same-uploader items as co-members (26\% of examples, 949 sources);
fusion appeared $+4.0$\,pp over frozen cosine on hard\_similar.
Restricting to true pack co-membership erases the gain
(Section~\ref{sec:fusion}).
%
\textbf{Regime dependence.}\enspace Leave-one-signal-out ablation
on the dev set shows tempo helps on hard\_similar ($-0.96$\,pp when
removed) but hurts on hard\_tempo\_key ($+0.68$\,pp); signals switch
sign across negative regimes, so a fused score averaging over them
cannot be uniformly trusted.
%
\textbf{Held-out uncertainty.}\enspace On a pre-committed 121-source
split, the fusion$-$cosine advantage on hard\_similar is $+1.5$\,pp
(bootstrap 95\%~CI $[-1.5, +4.7]$, crossing zero) under LAION-CLAP;
under MS-CLAP with source-weighted BPR it is $+9.2$\,pp (CI
$[+4.3, +14.3]$)---a $7.7$\,pp swing evidencing representation
sensitivity.
%
\textbf{Pilot divergence.}\enspace Nine raters on 20 blind A/B pairs
(Fleiss' $\kappa = 0.294$; one pair excluded for a ``neither''
majority) show a descriptive divergence between weak-label signal
rankings and human consensus.

\section{Conclusion}\label{sec:conclusion}
% ==================================================================

Pocket Producer operationalizes session-conditioned retrieval as a
user-controlled proposal in a production DAW\@.  It reads the live
session via the Nexus SDK, ranks candidates with a multi-signal
fusion, and surfaces per-signal evidence for preview; every insertion
is reversible and every interaction is logged.
Since offline evaluation shows the fusion advantage is sensitive to
label construction, embedding space, and negative regime, the default
ranker is a transparent rules baseline; the fusion serves as a
selectable alternative.  Evaluating whether preview and undo improve
creative outcomes, and personalization from logged feedback, is
future work.
