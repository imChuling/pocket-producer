\begin{abstract}
Music continuation need not coincide with audio similarity: the
loop that best matches a session is not necessarily the one that
best moves it forward.  Pocket Producer is a working prototype
integrated into the Audiotool DAW and designed around this
distinction.  It fingerprints the live session, ranks candidate
loops using pack co-membership as cold-start weak supervision, and
presents the results through an inspectable and reversible proposal
workflow.  Offline studies show that the apparent advantage of the
learned ranker is sensitive to label construction, negative regime,
and embedding representation.  These observations motivate a design stance in
which retrieval scores generate \emph{proposals} that musicians can
inspect, audition, insert, and undo, rather than final judgments
about what should come next.
\end{abstract}

\section{Introduction}\label{sec:intro}
% ==================================================================

When a musician returns to an unfinished loop-based project, the
question is not ``what sounds similar?''\ but ``what would be useful
as the next step?''
Loop compatibility~\cite{chen2020neuralloop,lattner2022samplematch,yi2024drum2bass,roychaudhuri2026loopmatcher},
stem coherence~\cite{ciranni2025cocola,nistal2024diffariff,riou2025stemretrieval},
session-conditioned generation~\cite{he2025tomi}, and reversible
co-creation~\cite{elkins2025dawzy} all address parts of this problem.
We define \textbf{continuation utility} as the property that a
candidate helps the musician make progress in the current session;
unlike pairwise audio similarity, it is directional and conditioned
on the evolving session context.

We contribute: (1)~a problem formulation that separates continuation
utility from similarity and compatibility; (2)~a working prototype
in a production DAW, engineered for revisability: live session
fingerprinting over the Nexus SDK, per-signal evidence,
single-transaction insertion whose undo also retracts the candidate
from the ranking context, and feedback logging; (3)~a tiered
negative-regime evaluation protocol with a fixed held-out
split that characterizes the sensitivity of weakly supervised
ranking to label construction, negative regime, and embedding
representation.

\subsection{Session Fingerprinting}\label{sec:fingerprint}

The live Audiotool session (Figure~\ref{fig:system}) is read via the
Nexus SDK, which exposes the project's tracks, regions, and
referenced audio samples.
The system extracts the project tempo from the document metadata and
collects up to eight unique audio samples referenced by regions in the
arrangement.  Each sample is embedded with
CLAP~\cite{elizalde2023clap}; the resulting vectors form the
session's timbral fingerprint.  When no session audio is available
(empty project or no sample-backed regions), the system falls back to
non-audio signals only.

\subsection{Multi-Signal Ranking}\label{sec:ranking}

Five signals score each FSLD~\cite{ramires2020fsld} candidate against
the session fingerprint:
(i)~mean-pooled and (ii)~max-pooled CLAP cosine similarity to session
samples, (iii)~tempo proximity, (iv)~key compatibility, and (v)~tag
Jaccard overlap between candidate tags and tags from the session's
audio fragments.
Writing $\phi(s,x)\in\mathbb{R}^5$ for these signals given session
$s$ and candidate $x$, the fusion scores each candidate as
$\sigma(w^\top\phi(s,x))$, with $w$ trained by BPR~\cite{rendle2009bpr}
on pack co-membership weak labels (Section~\ref{sec:fusion}):
\begin{equation}
\mathcal{L}_r(w) = -\,\mathbb{E}_{\mathcal{D}_r}
\big[\log\sigma\big(w^\top(\phi(s,x^+)-\phi(s,x^-))\big)\big],
\label{eq:bpr}
\end{equation}
where the expectation is over triples $(s,x^+,x^-)$ and $r$ indexes
the negative regime from which $x^-$ is drawn.
A hand-tuned \emph{rules} baseline over non-audio session signals
serves as the default ranker; the fusion is selectable and falls
back to rules when no session audio is available.

\subsection{Proposal Workflow}\label{sec:proposal}

The proposal workflow keeps creative authority with the musician:
every recommendation can be inspected, auditioned, inserted, and
undone.
\emph{Inspect}: each candidate carries per-signal evidence, reason
chips naming the signals that favored it (e.g., timbral closeness
to session regions, tempo fit, shared tags), so the musician can
judge whether those reasons apply to the current goal; signals that
contribute nothing emit no evidence.
\emph{Audition}: candidates can be previewed before insertion
without modifying the document.
\emph{Insert}: an accepted candidate enters the arrangement via a
single Nexus transaction.
\emph{Undo}: the most recent insertion can be reverted, which also
retracts the candidate's tags from the ranking context, so
subsequent recommendations are not biased by the undone choice.
Preview, insertion, rejection, and undo events are logged for future
personalization (not yet evaluated).

\subsection{Deployed Model}\label{sec:deployed}

The deployed ranker transfers the same five-signal recipe to the
musician's fragment library and is a separate production model with
four stated deltas: MS-CLAP embedding space (offline evaluation uses
LAION-CLAP Music); source-weighted BPR
(hard\_similar$\times$2.0, mean over 5 seeds); key constant zero
online (Audiotool documents lack key-signature metadata); tag
context drawn from session fragments rather than FSLD pack siblings.

\section{Cold-Start Weak Supervision}\label{sec:fusion}
% ==================================================================

At launch no interaction data exists, so the fusion is trained on
proxy supervision that predates any user: pack co-membership.
From the FSLD~\cite{ramires2020fsld} we kept only sounds with a
true Freesound pack (1,797 items, 605 packs), discarding items
grouped only by uploader.
Each eligible pack with at least three items yields one leave-one-out query per item, with
same-pack siblings as positives and cross-pack items as negatives in
three difficulty tiers (\emph{easy}: tempo/key mismatch;
\emph{hard\_tempo\_key}: compatible tempo and key;
\emph{hard\_similar}: highest cosine to the positive from another
pack).
A 121-source held-out split (seed 20260810) was fixed in version
control before any evaluation ran.
Development uses only the 484 train sources; the 171 with $\geq$3
items form queries (981 examples), the rest contribute negatives
only.
LAION-CLAP Music~\cite{wu2023laionclap} (512-dim) provides the
embedding backbone.

On the train side (mean over 5 source-grouped splits, each training
on ${\sim}75\%$ of train sources for 300 epochs, no early stopping),
frozen cosine reaches 0.929 overall and 0.814 on hard\_similar;
five-signal fusion reaches 0.925 and 0.813.
Under pack-only labels the fusion advantage is gone: $-0.03$\,pp on
hard\_similar, and fusion trails cosine on hard\_tempo\_key by
2.1\,pp on average (negative in all 5 splits).

\section{Observations}\label{sec:observations}
% ==================================================================

Three lines of evidence characterize the sensitivity of the
cold-start proxy.
%
\textbf{Label sensitivity.}\enspace An earlier corpus treated
same-uploader items as co-members (26\% of examples, 949 sources);
fusion appeared $+4.0$\,pp over frozen cosine on hard\_similar.
Restricting to true pack co-membership erases the gain
(Section~\ref{sec:fusion}).
%
\textbf{Regime dependence.}\enspace Leave-one-signal-out ablation
on the dev set shows tempo helps on hard\_similar ($-0.96$\,pp when
removed) but hurts on hard\_tempo\_key ($+0.68$\,pp); signals switch
sign across negative regimes.  In the terms of
Eq.~\eqref{eq:bpr}, the learned optimum $w^*$ depends on the
training mixture over regimes $\mathcal{D}_r$ rather than defining
a regime-invariant ranking.
%
\textbf{Held-out uncertainty.}\enspace An initial held-out run
trained each seed on a 75\% internal subset of train sources; after
identifying this as a protocol mismatch, we retrained on all 484
train sources and re-evaluated.  Table~\ref{tab:heldout} reports the
corrective results; the held-out split is therefore exploratory
rather than confirmatory.
Under LAION-CLAP the hard\_similar advantage is
$+2.1$\,pp with a bootstrap 95\%~CI crossing zero; under MS-CLAP
with source-weighted BPR (a sensitivity re-analysis on the same
split) it is $+9.9$\,pp, a $7.8$\,pp cross-configuration swing.
Hard\_tempo\_key shows near-zero deltas in both configurations,
with CIs crossing zero (the initial run showed a negative
hard\_tempo\_key delta under LAION-CLAP that disappeared after
the correction).

\section{Conclusion}\label{sec:conclusion}
% ==================================================================

Pocket Producer is a working prototype that operationalizes
session-conditioned retrieval as a user-controlled proposal
workflow in a production DAW: live fingerprinting, per-signal
evidence, reversible insertion, and feedback logging.
The default ranker is a transparent rules baseline requiring no
session audio; the fusion is selectable.  Future work includes evaluating whether
the proposal workflow improves creative outcomes, personalization
from logged feedback, and regime-robust ranking objectives.
